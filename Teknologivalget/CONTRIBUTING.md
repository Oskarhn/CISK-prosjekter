# Bidrag og endringer

Repositoryet fungerer både som driftsdokumentasjon og portfolio. Endringer må derfor være teknisk riktige og kunne spores til faktisk arbeid.

## Arbeidsflyt

1. Opprett en branch med et kort navn, for eksempel `docs/jellyfin-storage`.
2. Endre bare dokumentasjonen som påvirkes.
3. Oppdater dato eller versjon når status faktisk er kontrollert.
4. Kjør `./scripts/verify-public-repo.sh`.
5. Beskriv hva som ble kontrollert i commit-meldingen.

## Dokumentasjonskrav

- Skill mellom implementert løsning, historisk løsning og forslag.
- Ikke fyll inn manglende verdier ved å gjette.
- Bruk norsk tekst og etablerte engelske fagbegreper der det gir mer presis mening.
- Hold kommandoeksempler generiske og fjern credentials.
- Ikke kopier rå tredjepartstranskripsjoner eller annet materiale uten klar lisens.
